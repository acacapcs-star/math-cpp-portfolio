## 專案簡介
本專案收錄我在 C++ 學習過程中，結合數學概念與基礎演算法所完成的多個實作題目。
這些題目涵蓋二維與三維資料結構、模擬問題以及條件判斷與流程控制，

## 專題列表與說明
### 1. Bingo（小竹 Bingo）

在此題中，我一開始的直覺作法是，
每次叫到一個數字時，就重新走訪整個二維陣列，
逐一檢查所有座標，確認該數值所在的位置。

由於盤面本身是以二維陣列儲存，
空間複雜度為 O(N²)，
而若每次叫號都重新掃描整張盤面，
時間複雜度同樣會達到 O(N²)。

考量到此題會有多次叫號（最多可達數百次），
這樣的作法會造成大量重複的檢測。
因此我在讀入資料時，
額外建立一個「數值 → 座標 (x, y)」的對照結構，
先把每個數字在盤面中的位置記錄下來。

這樣在之後每次叫號時，
只需要直接查詢該數字對應的座標，
即可立刻更新該行、該列（以及斜線）的狀態，
避免反覆掃描整個盤面。

#### 複雜度分析
- **時間複雜度**：理論上仍為 O(N²)，但透過預處理大幅降低重複掃描的次數
- **空間複雜度**：使用 N × N 的二維陣列與額外的座標對照結構，整體為 O(N²)

### 2. Flood（淹水啦）

在一開始構思這題時，我的直覺作法是：
嘗試先假設每一層高度都能夠累積一層水，
再逐步判斷哪些區域會實際形成淹水。

然而在進一步分析後發現，
這樣的想法只適用於高度分布較單純的情況。
當地形的橫向面積很大、但各位置的高度不一致時，
是否能形成淹水，取決於「最低高度」是否能夠被完全包圍，
而不是單純看某一層是否存在空間。

因此在實作上，
必須從整體高度的最低層開始考慮，
逐層向上模擬水位的上升，
並確認在每一個高度下，
是否存在可以讓水流向外部的通道。
只有當該高度的所有可連通區域皆被封閉時，
該區域才會被判定為真正的淹水區域，並進行累積。

這樣的作法避免了只憑單一高度條件就做出判斷，
而是透過由低到高的整體檢查，
確保每一筆淹水的判定都符合實際地形的限制條件。

#### 複雜度分析
- **時間複雜度**：需要依高度層逐步進行檢查，整體仍屬於多次遍歷地形的模擬過程
- **空間複雜度**：主要使用地形高度的二維結構與輔助標記陣列，為 O(N²)
