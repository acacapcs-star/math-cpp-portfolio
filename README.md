## 專案簡介
在解ONLINE NTU CPC 的程式碼時,我赫然發覺了程式碼在不同自然科領域之間探討的邏輯的奧妙之處。
這些題目有包括了二維到三維這種跨維度的不同考題,由淺入深的探討著這塊程式碼實作領域,
從如何撰寫相異判斷式子,到如何在3d立體空間內的垂直找尋相對位置,都成功讓我對於空間向量以及相應的
換位思考邏輯有著更深層的理解與思維轉變。

## 撰寫之highlight 題目以及敘述
### 1. Bingo（小竹 Bingo）

在此題中，我一開始的直覺作法是，
每次叫到一個數字時，就重新走訪整個二維陣列，
逐一檢查所有座標，確認該數值所在的位置。

由於盤面本身是以二維陣列儲存，
空間複雜度為 O(N²)，
而若每次叫號都重新掃描整張盤面，
時間複雜度同樣會達到 O(N²)。

考量到此題會有多次叫號（最多可達數百次），
這樣的作法會造成大量重複的檢測。
因此我在讀入資料時，
額外建立一個「數值 → 座標 (x, y)」的對照結構，
先把每個數字在盤面中的位置記錄下來。

這樣在之後每次叫號時，
只需要直接查詢該數字對應的座標，
即可立刻更新該行、該列（以及斜線）的狀態，
避免反覆掃描整個盤面。

#### 複雜度分析
- **時間複雜度**：雖然時間複雜度並沒因為優化而改變,但透過
  "預處理"這個priority成功地“大幅降低”了重複掃描的次數
- **空間複雜度**：使用 N × N 的二維陣列與額外的座標對照結構,整體為O(N²)

### 2. Flood（淹水啦）

在一開始構思這題時，我的直覺作法是：
嘗試先假設每一層高度都能夠累積一層水，
再逐步判斷哪些區域會實際形成淹水。

然而在進一步分析後發現，
這樣的想法只適用於高度分布較單純==他的高度都是“統一為1層”的情況之下。
當地形的橫向面積很大,但各位置的高度不一致時,
是否能形成淹水,取決於「最低高度」是否能夠被"完全包圍"，
而不是"單純"看某一層是否存在空間。

因此在實作上，
必須從整體高度的"最低層"開始去探討，
逐層向上模擬水位的上升，
並確認在每一個高度下，
是否存在可以讓水流向外部的通道。
==假如已經被填滿,就必須要在判斷完成之後自動跳過那一格,避免重複計算到
只有當該高度的所有可連通區域皆被封閉時，
該區域才會被判定為真正的淹水區域,並開始進行累積。

這樣的作法避免：
”單一高度條件“就做出判斷，
而是透過由"低"到"高"的整體檢查，
確保每一筆淹水的判定都符合實際"地形的限制條件"。

#### 複雜度分析 
- **時間複雜度**：需要依高度層逐步進行檢查,整體仍屬於多次"遍歷地形"的相應模擬過程
- **空間複雜度**：主要使用地形高度的二維結構與輔助標記陣列,因此可視為O(N²)

### 3. Dark Particle（暗粒子）

在撰寫此題的初期，我的作法是分別紀錄兩顆粒子的"初始位置"與"速度"，
並假設它們在運動過程中皆為等速直線運動。
因此在每一個固定的 time lapse 中，
只需依據速度"方向與大小"，更新對應的”單位向量“即可。

實作碰撞判斷時，我一開始只在每個時間點檢查是否重疊，
後來才意識到這樣會錯過真正的碰撞瞬間。
一開始僅有考慮速度並“不足以”完整描述粒子的運動狀態，
還必須進一步“處理邊界條件”,例如上下左右的那種最邊緣的部分
當粒子碰觸到邊界時，會發生反彈,
且在不考慮"摩擦力"與"能量之耗損"的前提下，
反彈後的"運動距離"==原本的"起始"座標＋"原本移動距離的固定增加量"
以此確保在任意的t 秒後仍能計算出正確的位置,而不會隨意展示出偏差

此外，當兩顆粒子"發生碰撞"時，
其行為可視為"完全"彈性碰撞，
亦即兩者會互相交換"速度"&"方向"。
因此在最後時,我有增加一段程式:
"額外"加入此判斷機制,
優先計算粒子之間發生碰撞的"精確時間點"，
並在該時刻更新速度狀態，
以避免因離散時間步長造成位置或速度上的誤差。
可以在維持簡潔模型的情況下，
同時"正確處理邊界反彈與粒子碰撞"，
使整體模擬結果更加"精確且穩定"。

#### 複雜度分析
- **時間複雜度**：主要依時間步進進行模擬，並在每個步驟中進行常數次判斷
- **空間複雜度**：在本題設定下
- 需紀錄固定數量
  兩顆粒子:
  位置、速度與相關狀態,所需空間不隨輸入規模改變,
  因此可視為O(1)的空間使用情況。
